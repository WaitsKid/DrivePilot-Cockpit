# 02 软件需求规格说明书（SRS）

## 2.1 引言

本文定义 DrivePilot Cockpit v1.0.0 的功能需求、非功能需求、外部接口和验收标准。编号用于测试追踪和后续 Issue 管理。

## 2.2 功能需求

### 2.2.1 HMI 与系统框架

| 编号 | 需求 |
|---|---|
| FR-HMI-001 | 系统应提供固定设计尺寸的 QML 主画布，并在窗口变化时等比缩放。 |
| FR-HMI-002 | 系统应支持首页、应用、空调、设置、车辆、音乐、天气、助手、联系人、视频、计算器、画图和地图页面导航。 |
| FR-HMI-003 | 系统应提供全局状态栏、Toast 和关机确认组件。 |
| FR-HMI-004 | 页面切换不得中断 DMS 或 AI Agent 的全局连接。 |
| FR-HMI-005 | 用户偏好、应用收藏和常用次数应持久化。 |

### 2.2.2 空调、车辆与控制中心

| 编号 | 需求 |
|---|---|
| FR-VEH-001 | 用户可独立设置左右空调温度。 |
| FR-VEH-002 | 用户可设置风量和正常、除湿、加强、自动模式。 |
| FR-VEH-003 | 控制中心应模拟 WLAN、蓝牙、定位、旋转等开关。 |
| FR-VEH-004 | 车辆健康页应展示轮胎、电池、里程和能量流等模拟指标。 |
| FR-VEH-005 | 疲劳驾驶提醒开关关闭后，Qt 应停止 DMS 通信、隐藏状态图标并请求后台停止摄像头。 |

### 2.2.3 媒体、联系人和工具

| 编号 | 需求 |
|---|---|
| FR-MEDIA-001 | 系统应支持本地音乐播放、暂停、切歌和音量调整。 |
| FR-MEDIA-002 | 用户可导入媒体，运行时媒体文件不应被编译进可执行文件。 |
| FR-VIDEO-001 | 视频中心应支持本地视频列表、播放和导入。 |
| FR-CONTACT-001 | 系统应提供联系人、搜索、拨号和通话记录模拟。 |
| FR-CONTACT-002 | 联系人与通话记录应使用 SQLite 持久化。 |
| FR-TOOL-001 | 系统应提供科学计算器。 |
| FR-TOOL-002 | Vector Studio 应支持图形、文字、选择、拖动、填充和导入导出等绘图功能。 |

### 2.2.4 天气与导航

| 编号 | 需求 |
|---|---|
| FR-WEATHER-001 | 用户可按国内行政区搜索天气。 |
| FR-WEATHER-002 | 系统应展示当前、小时和多日天气数据。 |
| FR-WEATHER-003 | 搜索建议面板应支持选择、外部点击和再次点击按钮关闭。 |
| FR-MAP-001 | 系统应通过高德服务提供地点搜索、路线规划和导航步骤。 |
| FR-MAP-002 | 地图页面应使用 WebEngine 与 QML/C++ 交换数据。 |

### 2.2.5 语音与 AI Agent

| 编号 | 需求 |
|---|---|
| FR-ASR-001 | 用户可使用讯飞 WebSocket 进行流式语音识别。 |
| FR-ASR-002 | 识别可由用户手动完成，并支持静默自动提交。 |
| FR-AGENT-001 | Qt 应将用户文本通过 WebSocket 发送给独立 Agent 后端。 |
| FR-AGENT-002 | Agent 后端应支持工具调用、等待 Qt 执行结果并继续处理当前请求。 |
| FR-AGENT-003 | 界面应展示处理状态、待执行操作、工具结果和最终回复。 |
| FR-AGENT-004 | 工具必须在白名单中，参数应在 Qt 端再次校验。 |
| FR-AGENT-005 | Agent 应支持任务取消、会话重置、工具超时和最大步数限制。 |
| FR-AGENT-006 | 未配置 Kimi Key 时，应提供本地规则服务用于链路验证。 |

### 2.2.6 DMS

| 编号 | 需求 |
|---|---|
| FR-DMS-001 | DMS 后端应独占并后台读取本机摄像头，不在 Qt 中显示驾驶员画面。 |
| FR-DMS-002 | 系统应使用 YuNet 检测人脸和关键点。 |
| FR-DMS-003 | 系统应使用独立 MobileNetV2 模型识别眼睛和哈欠状态。 |
| FR-DMS-004 | 系统应计算持续闭眼时长、PERCLOS 和窗口内哈欠次数。 |
| FR-DMS-005 | 系统应输出活力、正常、略微疲劳、严重疲劳四级状态。 |
| FR-DMS-006 | 系统应提供升级/恢复防抖、无人脸重置和告警冷却。 |
| FR-DMS-007 | Qt 应按照 `event_id` 去重 Toast 和 TTS 告警。 |
| FR-DMS-008 | DMS API 不得提供摄像头帧获取接口。 |

## 2.3 非功能需求

| 编号 | 类别 | 需求 |
|---|---|---|
| NFR-001 | 性能 | Qt 主线程中的网络和推理调用不得同步阻塞 UI。 |
| NFR-002 | 性能 | MobileNetV2 ONNX 单模型 CPU P95 应低于 20 ms（目标机器）。 |
| NFR-003 | 可用性 | Python 服务离线时 Qt 其他功能仍应可用。 |
| NFR-004 | 可恢复性 | 后端重新启动后 Qt 应自动重连。 |
| NFR-005 | 安全 | API Key 不得写入仓库、QRC 或公开日志。 |
| NFR-006 | 隐私 | 默认不保存摄像头原始帧、个人照片和语音录音。 |
| NFR-007 | 可维护性 | QML 负责界面，C++/Python 负责状态、网络、数据和模型。 |
| NFR-008 | 可测试性 | Python 核心模块应有 pytest；关键用户流程应有手工验收清单。 |
| NFR-009 | 可移植性 | Python 服务使用路径配置；Qt 资源与运行时媒体分离。 |
| NFR-010 | 可追踪性 | Agent 工具调用应包含 `call_id`，DMS 告警应包含 `event_id`。 |

## 2.4 外部接口

- 摄像头：OpenCV `VideoCapture`；
- 讯飞 ASR：鉴权 WebSocket；
- 高德地图：Web 服务与 JavaScript API；
- 天气：Open-Meteo；
- Kimi：兼容 OpenAI Chat Completions 的 HTTPS API；
- DMS：REST + WebSocket；
- Agent：WebSocket；
- 本地文件：音频、视频、导入素材；
- 本地数据：SQLite 与 QSettings。

## 2.5 约束

1. 当前桌面版本以 Windows 为主要运行环境；
2. Qt 版本建议 6.9.1，最低按 CMake 配置为 6.8；
3. Python 建议 3.11；
4. 模型、数据集和密钥不随源码发布；
5. 项目仅模拟车控，不执行真实安全关键操作。

## 2.6 验收标准

- 三个进程可按文档启动；
- Qt 在后端离线时不崩溃；
- Qt 可自动连接 DMS 和 Agent；
- 典型 Agent 指令可产生真实工具调用和结果回传；
- 闭眼/哈欠可改变 DMS 状态并触发去重提示；
- 所有真实凭据均不在 Git 历史和源码中；
- 自动测试通过，上传前检查无严重问题。
