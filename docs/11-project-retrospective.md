# 11 项目复盘与后续路线图

## 11.1 七天迭代概览

项目采用阶段式增量开发，大致经历：

1. 清理工程、Toast 和基础路由；
2. 车辆健康、音乐和窗口自适应；
3. 公共页面框架、应用模型和偏好持久化；
4. 天气、语音识别、联系人、视频、计算器；
5. Vector Studio 与车辆设置；
6. 高德地图和行政区天气；
7. DMS 训练/部署、Qt 接入与 AI Agent 三端架构。

## 11.2 主要技术难点

### QML 工程化

- 多页面状态共享；
- 单例注册和 CMake QML 模块；
- 组件生命周期与全局服务；
- 固定设计画布缩放；
- 自定义控件替代原生桌面样式；
- MSVC 下绘图性能和重绘控制。

### DMS

- 不能把 Closed/Open/yawn/no_yawn 直接当成四级疲劳；
- 需要拆成两个视觉分类器；
- 单帧分类必须与时间窗口结合；
- 验证集高分不代表真实摄像头泛化；
- Qt 不应承担摄像头和模型推理。

### Agent

- Qt 直连模型虽能运行，但会暴露 Key 并放大 C++ 复杂度；
- 最终改为 FastAPI Agent；
- 工具必须由 Qt 执行并返回真实结果；
- 高级感来自实时计划和执行轨迹，而不是泄露完整隐式思维链。

## 11.3 做得较好的设计

- QML 与 C++/Python 职责清晰；
- DMS 和 Agent 都是独立可测试服务；
- API Key 全部外置；
- DMS 摄像头帧不跨进程；
- Agent 工具白名单与参数双重校验；
- 测试、模型指标和失败降级均有记录；
- 增量阶段最终整理为一个可读的 monorepo。

## 11.4 已知限制

1. UI 来源于教学项目并经过扩展，部分视觉素材授权需在商业使用前重新确认；
2. DMS 数据规模和场景多样性不足，不能用于真实安全系统；
3. 未实现头部姿态、视线、遮挡和夜间红外检测；
4. Agent 工具数量有限，没有权限确认层和长期记忆；
5. 导航依赖 WebEngine 和第三方地图服务；
6. 未接入 CAN/Modbus/真实硬件；
7. Qt 自动化 UI 测试和跨平台 CI 尚不完整；
8. 运行与部署仍以开发环境为主。

## 11.6 面试讲解主线

建议按以下顺序讲：

1. 为什么选择“三端解耦”；
2. QML 页面与 C++ 单例如何协作；
3. DMS 为什么是两个分类模型加时间状态机；
4. ONNX 一致性和性能如何验证；
5. Agent 工具调用为什么由 Qt 最终执行；
6. 如何处理密钥、摄像头和个人数据；
7. 哪些部分是模拟，生产化还需要什么。

重点不是宣称“做成了量产车机”，而是能清楚解释每个设计取舍、验证方法和限制。
